市场策略

Land and Expand

先用高价值、强服务的独立验收（Assurance）作为楔子，切入一个权限 清晰、风险高的企业 Agent 项目；验收建立信任并沉淀威胁模型、业务 边界和攻击证据后，再把 Guard 接入生产/准生产环境，逐步转化为持续 订阅与复测收入。

Land（着陆）

首要客户应是正在采购或部署高权限 Agent 的业务企业，优先验证金融/财务、采购和内部工具工作流等场景。模型厂商、集成商可作为后续渠道，但不应削弱 Sentinel 作为独立第三方的定位。

Expand（扩张）

验收过程中沉淀的威胁模型、攻击轨迹和业务边界，直接成为部署 Sentinel Guard 与 Continuous Assurance 的基础，把一次性项目收入逐步转化为经常性收入。

组织能力

早期由 CEO 牵头客户发现、产品定义与前几单销售，CTO 与 Chief Scientist 深度参与技术型售前和交付；同时优先补强 ToB 安全销售、产品工程和中国市场落地能力。

商业模式

从项目收入到安全基础设施

当前尚缺少经过客户验证的定价、ACV、毛利率和销售周期数据。投资人版 财务模型应在完成首批 5-10 个设计合作/付费项目后，用真实数据替代 假设，而不是过早依赖自上而下的市场规模预测。

阶段 客户购买什么 收费逻辑 战略目的
1. 首次验收 Sentinel Assurance 按项目/系统收费 进入客户、获得真实 Agent 和安全数据
2. 正式上线 Sentinel Guard 企业订阅 + Agent/调用规模 形成经常性收入和产品粘性
3. 系统更新 Continuous Assurance 复测、升级与年度服务 将模型变化转化为持续安全需求
4. 生态化 评级/标准/审计接口 企业级合同、生态合作 进入采购、保险、审计与标准流程
深圳与中国市场

重要的产业验证基地，而非战略转向

深圳应被视为 Sentinel 的重要产业验证与中国落地基地，而不是改变 产品最初的滩头市场。短期仍优先验证企业采购/财务 Agent 和拥有内部 工具权限的工作流 Agent；在此基础上，深圳的机器人、智能制造、无人 机和出海企业为 Sentinel 提供向"物理行动"和跨境业务扩展的独特场景。

第一阶段

与深圳企业验证高权限软件 Agent 场景，例如采购、财务、内部工具调用和跨境业务流程，形成可复用的 Assurance + Guard 案例。

第二阶段

在核心平台成熟后扩展到机器人、无人机和智能制造等具身智能场景，验证设备控制、物料调度和物理动作的安全边界；作为 Sentinel Agent Security 能力的延伸，而非早期同时铺开的第二条产品线。

目标是与 3-5 家深圳企业建立设计合作伙伴关系，优先选择能够形成可 公开案例或可复用行业模板的合作。对敏感企业数据支持私有化/本地化 部署，避免核心业务数据离开企业环境。

仍需验证的关键假设

作为早期项目，这些是尚未解决的问题

投资人应把这些视为未来 6-12 个月的核心去风险任务，而非已经解决的问题。

  • →运行时 Guard 能否在足够低的延迟和误报率下，对复杂 Agent 行为做出可靠裁决？
  • →AAL 是否能在不同 Agent、不同实验室和不同时间保持足够的可重复性和可解释性？
  • →客户真正的预算拥有者是 CISO、CIO、AI Platform Team、采购/风险部门还是业务负责人？
  • →企业更愿意购买第三方验收、持续安全软件，还是将其打包进现有安全供应商？
  • →高校背景 IP、学生项目、开源组件和未来公司 IP 的边界需要在融资前清晰化。
