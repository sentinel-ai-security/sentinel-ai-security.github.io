为什么是现在

AI 风险正在从"内容风险"升级为"行动风险"

传统生成式 AI 主要输出文本；Agent 则能够规划、多步执行，并连接企业 内部数据、浏览器、数据库、代码环境、MCP/工具和外部系统。当这些智能体 被赋予付款、审批、修改记录或控制设备等权限后，一次间接提示词注入或 权限越界，就可能导致灾难性的资金损失、数据泄露或物理破坏。

⚖️

监管正在迁移

NIST 与英国 AI 安全研究所（AISI）正把关注重心从模型安全转向 Agent 身份、授权与可控行动。

🔓

信任缺口是结构性的

业务企业通常没有自己的 AI Red Team；而供应商自证安全，本身就存在"开发者同时是安全裁判"的信任冲突。

🔄

一次性测试远远不够

模型、Prompt、知识库、工具与攻击能力持续变化，一次性的上线前测试无法覆盖持续演进的风险。

产品体系

覆盖 Agent 全生命周期的一套安全闭环

Sentinel 不是把三个模块分别出售，而是一个完整闭环：首次验收既是收入 来源，也是获取真实攻击数据、业务边界和客户工作流的入口；运行时保护 形成高频使用和长期订阅；系统变化进一步带来自动复测和持续安全证据。

1 敢不敢上线？

Sentinel Assurance

上线前独立第三方验收，代表业务企业对 Agent 进行红队压力测试与风险量化。

  • 自动化与人工结合的对抗测试
  • Prompt Injection、工具误用、数据泄露、目标劫持
  • 权限使用边界与敏感操作边界识别
➔
2 这一步能不能执行？

Sentinel Guard

作为 Agent 与真实业务系统间的安全网关，在关键动作执行前进行毫秒级拦截。

  • 输入检查、意图理解与工具调用验证
  • 数据访问与输出内容审查
  • 允许 / 阻断 / 人工审批，并留存审计证据
➔
3 现在依然安全吗？

Continuous Assurance

模型、工具或权限变更时自动触发影响评估与复测。

  • 模型 / Prompt / RAG / 工具 / 权限变化检测
  • 自动生成测试用例执行复测
  • 更新 AAL 安全等级，并反哺 Guard 策略
更多 Assurance 验收 → 更多攻击与失败轨迹 → 更强的 Guard 策略 → 更多生产环境证据 → 更准确、更低成本的 Assurance
不只是一份漏洞清单

我们回答 CISO 真正关心的问题

Red Teaming、安全扫描和 Guardrail 已经在模型与内容安全上形成重要能力。 Sentinel 更进一步：量化一个 Agent 究竟可以被赋予多大的真实业务权限， 并让这个答案随 Agent 的变化持续保持准确。

"这个 Agent 可以上线" 不是一个有用的答案。"在自动化攻击者、灰盒信息条件 下，这个 Agent 可以被安全地赋予 AAL 3 级别的权限" 才是。
